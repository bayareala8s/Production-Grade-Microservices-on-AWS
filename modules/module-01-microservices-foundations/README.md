# Module 1 — Microservices Foundations (Enterprise Reality)

## Goal

Teach students **when microservices make sense** and how to design them like production teams:

- bounded contexts and ownership
- data ownership per service
- sync vs async communication
- failure modes and “operability first” thinking

## Outcomes

Students will be able to:

- evaluate monolith vs microservices tradeoffs
- draw a bounded-context map and service ownership model
- identify cross-service data flows and failure modes
- write a service contract (OpenAPI + event contract) at a high level

## Prerequisites

- basic REST API understanding
- familiarity with Docker and AWS concepts (VPC, IAM) is helpful but not required here

## How this module fits the course

Module 1 creates the **design foundation** for the rest of the course. Modules 2–8 implement these principles in code, infra, and operations.
